# Supervisor WHITE ROOM

Supervisor работает из репозитория. Python-файл из Downloads больше не участвует в запуске.

## Запуск

Из корня проекта выполните:

~~~bash
scripts/supervise --status
scripts/supervise run
scripts/supervise report
~~~

Для запуска нужен чистый коммит владельца с утверждённым планом, Python 3.12+, Codex CLI, Git с настроенным автором, Mise, установленный Rust с rustfmt и Clippy, Node, локальный кеш Cargo и Linux с работающим bubblewrap. Supervisor использует текущую авторизацию Codex. Ветки, незакоммиченные правки и индекс владельца сохраняются. По окончании появится отчёт в консоли и в приватном каталоге .supervisor/. Команда run продолжает тот же план и восстанавливает сохранённую фазу кандидата.

M1 закрыт. Результат приёмки и Git-чекпоинт записаны в журнале. Когда следующий этап ожидает одобрения, `report` показывает завершённый этап, а `run` и `--status` возвращают код 3. [Журнал завершённых работ](../tasks/completed.md)

## Утверждение этапа

Владелец выбирает порядок работ в tasks/supervisor-plan.json, сверяет записи в docs/decisions.md и .agent/state.json, затем фиксирует план своим коммитом. Идентификатор phase должен совпадать с текущим этапом, статус должен быть approved_for_implementation, а decision должен ссылаться на строку Approved by owner в журнале решений. При смене этапа владелец обновляет эти записи.

- У задачи routine есть уникальный id, заголовок, измеримые criteria и список точных paths. Пути ограничены статической частью интерфейса, popup расширения и отдельными Rust-исходниками. Основные файлы, которые реализуют сбор данных, запуск задач и песочницу, требуют ручного разбора. Приёмка может дополнительно запускать указанные владельцем тесты Node из tests/supervisor-acceptance/ через поле acceptance. Эти тесты должны быть заранее зафиксированы и защищены от изменений Codex.
- У задачи owner список paths пуст. Используйте её для решения о продукте, ручной приёмки, работы с разрешениями, приватностью или безопасностью. Supervisor остановится на первой такой задаче. После решения владелец фиксирует результат и утверждает обновлённую очередь.
- Время и число итераций ограничены для каждого запуска. Число попыток ограничено для каждой задачи. Выполнения Codex и токены накапливаются в рамках утверждённого плана. Supervisor останавливает следующие вызовы при исчерпании квоты и останавливает работу, если CLI не вернул данные об использовании. Codex CLI возвращает токены после вызова, поэтому текущий вызов может превысить остаток. Для жёсткого денежного лимита или ограничения внутренних API-запросов нужен лимит на стороне провайдера.

## Проверки и восстановление

Builder получает отдельный снимок и sandbox workspace-write без сети и запросов повышения прав. Reviewer получает новый сеанс с read-only sandbox и копию прошедшего проверки кандидата. Проверки идут в отдельном bubblewrap без сети и с чистым окружением. Запускаются rustfmt для изменённых Rust-файлов, Cargo check, Clippy с обязательной группой correctness, Rust unit- и pilot-тесты, проверка синтаксиса JavaScript и браузерные тесты согласия. Утверждённые тесты задачи добавляются к этому списку. Проверки реального рабочего стола и системные тесты изоляции проходят отдельно на подходящем окружении.

Checkpoint требует кода выхода 0 от тестов, подтверждения всех критериев Reviewer и проверки точного набора файлов. Коммиты остаются в локальной ветке supervisor/<этап>-<идентификатор-плана>. Для просмотра используйте git show <хеш-из-отчёта>. Перенос проверенных коммитов в основную ветку делает владелец. Не открывайте ветку checkpoint в другом worktree во время запуска.

Повторный run после кода 4 продолжит с сохранённой фазы. Код 3 требует решения владельца. Код 1 сигнализирует об ошибке запуска, конфигурации или окружения. Если проверка выявила проблему в исходном дереве, отчёт покажет путь к baseline.log. Логи проверок и незавершённый кандидат хранятся локально в .supervisor/. Состояние плана привязано к исходному HEAD, чтобы продолжение не переписало чужую работу.

Без вызова Codex доступны:

~~~bash
python3 -B -m unittest discover -s tests -p test_supervisor.py
scripts/supervise check
~~~
