# Когнитивный движок

> Как WHITE ROOM моделирует знания пользователя, планирует сессии и адаптирует сложность.
> Пометки: **[R]** — механизм основан на исследованиях (см. `scientific-foundations.md`), **[H]** — гипотеза, которую нужно проверить на данных.

## 1. Принципы

1. **Измерять только наблюдаемое.** Модель строится на ответах, решениях, ошибках и времени ответа. Не на нажатиях клавиш и не на «focus score».
2. **Простые модели, понятные пользователю.** У каждого решения планировщика должно быть объяснение одной строкой: «эту тему ставим сейчас, потому что вероятность вспомнить упала до 70%».
3. **Детерминированное ядро, LLM на периферии.** Планирование, расписание и оценки — алгоритмы. LLM генерирует контент и разбирает свободные ответы, но не принимает решений о расписании.
4. **Никаких выводов про интеллект.** Модель описывает знания по конкретным темам, а не «способности» человека.

## 2. Модель данных

```
Domain (Mathematics, German, ...)
 └─ Topic           граф тем: «производная» → требует «предел»
     └─ Skill       умение, которое можно проверить: «дифференцировать сложную функцию»
         └─ Item    конкретная единица проверки
               ├─ Card     вопрос — ответ (факт, слово, определение)
               ├─ Problem  задача с проверяемым ответом (число, выражение, тест кода)
               └─ Prompt   свободный ответ (объяснение), проверяется LLM, с пометкой надёжности
```

- **Item** — единица для FSRS (память).
- **Skill** — единица для модели навыка (умение решать новые задачи).
- **Topic** — для планирования и графа зависимостей.

Каждая попытка (`Attempt`) хранит: item, время, результат (верно / частично / неверно / подсказка), время ответа, уровень подсказки, прогноз пользователя (для калибровки), контекст сессии.

## 3. Три уровня модели

### 3.1 Память: FSRS для каждого item [R]

- Используем `fsrs-rs` — ту же реализацию, что в Anki.
- Оценки «снова / трудно / хорошо / легко» **выставляются автоматически**, где ответ проверяется (задачи, код, точное совпадение): неверно → «снова», верно с подсказкой → «трудно», верно → «хорошо», верно и быстро → «легко». У карточек оценку ставит пользователь. Это убирает основную причину ошибок FSRS — нечестные оценки.
- Желаемый уровень запоминания задаётся по домену. По умолчанию 0.90; для «экзамен через 2 недели» можно поднять.
- Параметры FSRS переобучаются на данных пользователя примерно после 1000 повторений. До этого — параметры по умолчанию.

### 3.2 Навык: байесовская оценка по skill [R/H]

FSRS не отвечает на вопрос «умеет ли человек решать **новые** задачи этого типа». Для этого отдельная модель.

**Вариант для MVP: Beta-Bernoulli с забыванием.**
- Для каждого skill хранится Beta(α, β) — распределение вероятности решить новую задачу этого типа.
- Обновление: верно → α += w, неверно → β += w; вес `w` меньше при подсказке.
- Забывание: со временем α и β сжимаются к априорным значениям, неуверенность растёт.
- Считаются только **задачи, которые человек раньше не видел** (первая попытка). Повторы того же item идут в FSRS, а не сюда. Именно это отделяет понимание от заучивания ответа.

**Почему не Deep Knowledge Tracing.** Khajah, Lindsey, Mozer (2016): BKT с простыми расширениями (давность, индивидуальные способности, сходство навыков) **не хуже** DKT. [arXiv](https://arxiv.org/abs/1604.02416). У одного пользователя данных мало: нейросеть переобучится, и её решения нельзя объяснить.

**Позже (фаза 3):** BKT или PFA (performance factors analysis) с учётом графа тем, если данных станет достаточно. *Сравнение PFA с другими методами в этом исследовании не проверено.*

### 3.3 Граф тем: готовность к новому материалу [H]

- Тема считается открытой для изучения, когда навыки-предпосылки освоены (например, средняя вероятность решения ≥ 0.7).
- Если человек ошибается в новой теме, планировщик проверяет предпосылки: часто проблема на шаг раньше.
- Граф для домена создаётся вместе с пользователем: LLM предлагает, человек правит. Генерированный граф без проверки не используется.

## 4. Планировщик сессии

### 4.1 Вход
- Цель сессии (из онбординга): «выучить X», «решить задачи по Y», «повторить», «исследовать Z».
- Время: 30 минут – 4 часа.
- Состояние модели: какие items пора повторять, у каких skills высокая неуверенность, какие темы открыты.
- Самооценка (по желанию): сон, энергия.

### 4.2 Структура блока [R]
```
[ 2 мин ]  Прогрев: 3–5 вопросов по прошлой сессии (retrieval, без подсказок)
[ 20–45 ]  Основная работа: изучение нового или задачи
            ├─ новый материал: сначала попытка решить (productive failure), потом разбор
            ├─ новичок в теме: разобранный пример → пример с пропусками → задача
            └─ похожие типы задач: перемешивать (interleaving)
[ 3–5 мин ] Проверка блока: вопросы по только что изученному + прогноз результата
[ 5–15 мин ] Перерыв: встать, без экрана; перед ним одна строка «где остановился»
```

### 4.3 Длина сессии и блоков
- **По умолчанию:** блоки 25–50 минут, перерывы 5–15 минут, после каждых ~90 минут — длинный перерыв 15–30 минут. Это **разумные значения, не научный оптимум** (оптимальной длины не установлено).
- **Адаптация [H]:** если точность во второй половине блока регулярно ниже первой, а время ответа растёт, следующий блок укорачивается. Если падения нет, удлиняется. Шаг 5 минут, пределы 15–60.
- **Сессия 4 часа** допустима, но: не больше 3 часов основной работы, обязательные перерывы. Если точность падает, сессия заканчивается раньше, с сообщением: «Ты устал, эффективность упала. Остаток лучше перенести на завтра». Это честно и следует из данных о перерывах и сне.

### 4.4 Выбор материала
Простая взвешенная очередь, а не оптимизатор:
1. Items, у которых вероятность вспомнить ниже желаемой (по FSRS) — до 20–30% времени сессии.
2. Новые задачи по skills текущей цели, сложность — вероятность решения около 0.6–0.8 [H]: достаточно трудно, но выполнимо.
3. Новый материал — только если открыты предпосылки.
4. Потолок новых items в день, чтобы не создать завал повторений через неделю.

### 4.5 Подсказки по уровням [R]
Уровни: (1) намёк на направление → (2) какой метод или факт нужен → (3) первый шаг → (4) полное решение. Каждый уровень снижает вес попытки для модели навыка. ИИ **не показывает** уровень 4, пока не было собственной попытки (урок Bastani и др., 2025).

## 5. Обнаружение усталости [H]

Используем только наблюдаемые сигналы:
- Падение точности в блоке относительно личного уровня по этому skill.
- Рост времени ответа при той же сложности.
- Самооценка в перерыве (шкала 1–5, одно касание).
- Рост переключений окон вне плана (если включено).

Сигнал — это **предложение** перерыва, а не принудительная остановка. Исключение: жёсткий потолок длины сессии, который задаёт сам пользователь.

Не используем: ego depletion, «запас силы воли», камеру, анализ лица.

## 6. Отложенная проверка: главная метрика

- После каждой сессии создаётся небольшой набор контрольных вопросов (5–10) по её содержанию. Это не те же items: другие формулировки и новые задачи того же типа.
- Они возвращаются через **1, 7 и 30 дней**, отдельно от обычных повторений.
- Результат на «7 и 30 дней» — основная цифра на экране прогресса: «Из изученного 2 недели назад ты удерживаешь 68%, решаешь новые задачи — 54%».

## 7. Калибровка [R]

- Перед проверкой блока: «сколько из 5 ответишь правильно?»
- График «прогноз против факта» по неделям. Хорошая калибровка — сама по себе цель метапознания.
- Если пользователь систематически переоценивает себя, планировщик ставит больше проверок и меньше нового.

## 8. Эксперименты на одном человеке (n-of-1) [H — оригинальная идея]

Многие эффекты (шум, музыка, длина блока, interleaving, время обратной связи) **сильно зависят от человека**. Вместо общих советов WHITE ROOM может их проверить:

1. Пользователь выбирает вопрос: «помогает ли мне розовый шум?»
2. Сессии случайно распределяются по условиям (с шумом / без), по 6–10 на условие.
3. Сравнивается **отложенная** точность по материалу этих сессий, а не самочувствие.
4. Результат с честной неуверенностью: «разница +4%, 90% интервал от −3% до +11% — нельзя сказать, что помогает».

**Ограничения:** эффекты переноса между сессиями, разная сложность материала, мало наблюдений. Показывать интервалы, а не p-значения; не ставить эксперименты на важный материал перед экзаменом.

## 9. Генерация контента и контроль качества

| Источник item | Проверка ответа | Надёжность |
|---|---|---|
| Пользователь написал сам | Точная или самооценка | Высокая |
| Импорт из Anki | Самооценка | Высокая |
| LLM из материала пользователя | LLM + пометка, кнопка «вопрос неверный» | Средняя |
| Задача по коду с тестами | Запуск тестов в песочнице | Высокая |
| Задача по математике с ответом | Числовая или символьная проверка | Высокая |
| Свободное объяснение | LLM-разбор, только качественный отзыв | Низкая: в модель навыка идёт с малым весом |

- Сгенерированные items до первого использования показываются коротким списком «проверь и отбрось лишнее» (30 секунд на 10 вопросов).
- Item, помеченный «неверный», убирается и не учитывается в модели.

## 10. Что модель **не** делает

- Не оценивает IQ, «скорость мышления» и «когнитивный уровень».
- Не делает выводов о «деградации» по пропущенным дням.
- Не сравнивает пользователя с другими людьми.
- Не использует время в приложении как показатель знаний.
