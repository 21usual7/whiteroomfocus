# Спецификация продукта WHITE ROOM

> Связанные документы: `scientific-foundations.md` (почему), `cognitive-engine.md` (как модель работает), `technical-feasibility.md` (на чём строить), `implementation-roadmap.md` (в каком порядке).

## 1. Пересмотр исходной концепции

Что в исходной идее работает, а что я предлагаю изменить:

| Исходная идея | Оценка | Предложение |
|---|---|---|
| Режим концентрации + домены | Верно, но домены — не главное | Ядро общее для всех доменов: вспоминание, интервалы, проверка. Домен — это **адаптер**: типы items, способ проверки, инструменты |
| Онбординг через ИИ, «персональный протокол» | Риск: LLM придумает правдоподобный, но произвольный план | Протокол собирает **детерминированный** планировщик из шаблонов. ИИ только задаёт уточняющие вопросы и готовит контент |
| Сессии до 4 часов | Данных о пользе длинных сессий нет | 4 часа можно, но с обязательными перерывами, потолком основной работы ~3 ч и досрочным завершением, когда точность падает |
| ИИ-мониторинг активности | Сигналы слабые, риск для приватности | Мониторинг — только опция и только как контекст. Главный сигнал — ответы на вопросы |
| «Тренировка устойчивости к отвлечениям» | Нет доказательств, вероятен вред | Не делать |
| Эстетика White Room | Хорошо для атмосферы | Только визуально: белый минимализм, тишина. Без давления, наказаний, рейтингов и изоляции |
| Блокировка приложений | Полезна как самообязательство | Мягкая, прозрачная, с аварийным выходом |

**Позиционирование одной фразой:** WHITE ROOM — это не таймер концентрации, а **петля, в которой каждая сессия проверяется через неделю**.

## 2. Пользователи

- **Основной:** самостоятельно обучающийся технический специалист или студент на Linux. Учит математику, программирование, security, язык. Ценит приватность и контроль.
- **Не целевые сейчас:** дети (данные Sinha и Kapur 2021 показывают другие эффекты для младших), команды и учителя, мобильные пользователи.

## 3. Основной сценарий

```
Главный экран
  ├─ «Сегодня»: что повторить (N), контрольные проверки (M), продолжить цель
  ├─ [ Войти в комнату ]
  └─ Прогресс: удержание через 7/30 дней, новые задачи, калибровка

Вход в комнату
  1. Выбор цели (или продолжить существующую)
  2. Онбординг цели (только для новой цели, 1–3 минуты)
  3. План сессии: блоки, перерывы, что проверим — пользователь может изменить
  4. Подготовка окружения: что блокировать, какие приложения нужны, звук
  5. Сессия
  6. Итог: что сделано, прогноз против факта, что вернётся и когда
```

### 3.1 Онбординг цели
Вопросы (ИИ уточняет только при неясности, иначе используются формы):
1. Что хочешь уметь в конце? (свободный текст → ИИ предлагает 3–7 проверяемых skills, пользователь правит)
2. Что уже знаешь? → **короткий входной тест** (5–10 вопросов) вместо самооценки, ведь самооценка ненадёжна
3. Срок: «к экзамену 15 декабря» / «без срока»
4. Материалы: файлы, ссылки, учебник, курс
5. Нужные приложения: IDE, браузер, PDF-просмотрщик, терминал, VM — это станет списком разрешённых

### 3.2 Во время сессии
- Минимальный интерфейс: текущая задача, таймер блока (можно скрыть), кнопка «застрял» (подсказки по уровням), буфер для посторонних мыслей.
- **Буфер мыслей:** горячая клавиша → одна строка → возврат к работе. После сессии буфер показывается.
- **Аварийный выход:** горячая клавиша и пункт в трее. Мгновенно снимает блокировку, завершает сессию, ничего не спрашивает. Последствий нет.
- Перерыв: экран предлагает встать и не смотреть в экран. Перерыв можно пропустить, но пропуск записывается, а в итоге сессии показывается.

### 3.3 Итог сессии
- Проверка: 3–10 вопросов + прогноз результата перед ней.
- «Ты прогнозировал 4/5, получил 2/5. Это нормально: ощущение понимания обычно опережает реальное».
- Что вернётся и когда.
- Одна строка рефлексии (по желанию).

## 4. Домены

Каждый домен определяет: **типы items**, **способ проверки**, **режимы**, **инструменты**.

### 4.1 Mathematics
| Режим | Что происходит | Проверка |
|---|---|---|
| Learning | Сначала попытка → разбор → пример с пропусками → задача | Числовой или символьный ответ (CAS) |
| Problem Solving | Перемешанные задачи похожих типов (interleaving), подсказки по уровням | CAS; для доказательств — самопроверка по эталону + LLM-разбор |
| Recall | Определения, теоремы, формулы: карточки FSRS | Самооценка / точная |

Особенности: ввод LaTeX с предпросмотром; поле «объясни ключевой шаг» (self-explanation).

### 4.2 Programming
| Режим | Что происходит | Проверка |
|---|---|---|
| Learning | Концепция → маленькая задача сразу | Тесты в песочнице |
| Implementation | Собственный проект пользователя, цель на блок | Цель достигнута по критерию пользователя + тесты, если есть |
| Debugging | Код с подброшенной ошибкой; найти и объяснить | Тест проходит + объяснение |
| Problem Solving | Задачи алгоритмического типа | Тесты |

Интеграция с IDE (фаза 2): запуски тестов и ошибки компиляции как контекст сессии. ИИ не пишет код за пользователя в режимах Learning и Problem Solving.

### 4.3 Cybersecurity
| Режим | Что происходит | Проверка |
|---|---|---|
| Research | Чтение CVE, статей, write-ups порциями (incremental reading) → вопросы | Вспоминание |
| Labs | Работа в своей лаборатории (VM, HTB/THM, CTF) — WHITE ROOM ведёт журнал и цели, сам лабы не запускает | Флаг или критерий цели + отчёт «что сработало» |
| Reverse Engineering | Задача (crackme, бинарь), инструменты (Ghidra, gdb) разрешены | Ответ или флаг + объяснение |
| Practice | Карточки по командам, классам уязвимостей, портам; interleaving по похожим атакам | FSRS |

Важно: WHITE ROOM работает только с лабораториями пользователя; никакой автоматизации атак.

### 4.4 German
| Режим | Что происходит | Проверка |
|---|---|---|
| Vocabulary | Слова в контексте предложения, оба направления | Точное совпадение с допуском опечаток, артикли отдельно |
| Grammar | Перемешанные похожие конструкции (Dativ/Akkusativ, порядок слов) | Точная / LLM для свободных |
| Production | Написать 3–5 предложений по теме | LLM-разбор ошибок, без оценки |
| Listening/Reading | Текст или аудио пользователя → вопросы | Вспоминание |

Особенности: музыку со словами во время сессий по немецкому не предлагать.

### 4.5 Research
| Режим | Что происходит | Проверка |
|---|---|---|
| Reading | Статья порциями; после каждой — «что главное своими словами?» | LLM сравнивает с текстом, отмечает пропуски |
| Synthesis | Связать 2–3 источника: что общего, где противоречия | Самопроверка + LLM |
| Recall | Ключевые утверждения и их источники | FSRS |

### 4.6 Custom
Пользователь задаёт: название, skills, типы items (карточка / задача с ответом / свободный ответ), разрешённые приложения. Тот же движок.

## 6. Нефункциональные требования

- Фоновый процесс < 50 МБ RAM, без опроса раз в секунду.
- Интерфейс доступен с клавиатуры полностью; контраст по WCAG AA; масштабирование шрифта; темная тема (белая «комната» — тема по умолчанию, но не единственная).
- Никаких серий дней, лиг, рейтингов и уведомлений «ты нас забыл». Напоминание о повторениях — максимум одно в день, по согласию.
- Пропуск дней не наказывается: накопившиеся повторения распределяются на несколько дней.

## 7. Экран прогресса

Что показываем:
1. **Удержание:** % верных ответов на контрольных через 7 и 30 дней, по доменам, тренд за 8 недель.
2. **Понимание:** % первых попыток новых задач, по skills.
3. **Калибровка:** прогноз против факта.
4. **Прогноз забывания:** сколько items упадёт ниже порога в ближайшие 7 дней.
5. Время — **внизу и серым**, как контекст, а не как достижение.

Чего не показываем: «focus score», «когнитивный уровень», сравнение с другими.

## 8. Этические ограничения

- Не оптимизируем экранное время и частоту возвратов.
- Не используем тревогу (серии, «потеряешь прогресс»).
- Перерывы, аварийный выход, доступность не отключаются никакими «жёсткими» режимами.
- Никаких обещаний про интеллект; формулировки в интерфейсе проверены на соответствие `scientific-foundations.md`.
