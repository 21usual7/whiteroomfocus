## Этапы

### 1. Рабочий день, цели, непрерывность — сделано

- Ядро `whiteroom-core/src/learn.rs`: цель из модуля (группа `goal`, пилот не затрагивается), правка названия, порядка навыков, материалов (ссылка http(s) или абсолютный путь + область использования), срока, длительности блока; редактируемый граф предпосылок с отказом на цикл.
- Воспроизводимый план: входная диагностика → повторения по сроку → новая работа по навыкам → перерывы каждые 25 мин → итоговая проверка на переносе с чередованием навыков. У каждого шага — причина выбора. После диагностики неотредактированный остаток плана пересобирается: подготовленный ученик пропускает разобранный пример и шаг с пропуском.
- Блок хранится в SQLite: шаги, подсказки, заметка «где остановился», буфер мыслей. Ответ на шаг идемпотентен (двойной клик, второй клиент) — `block_step` с первичным ключом; один открытый блок на базу (уникальный частичный индекс). Завершение в любой момент, энергия и рефлексия добровольны.
- «Сегодня»: продолжить блок, проверка (с окном), повторения (с давностью и предложением распределить при > 20), продолжение цели (со сроком); пустое состояние с примером; нейтральное сообщение о перерыве.
- CLI: `today`, `goal`, `goal add`, `learn`, `spread`. Окно — экраны «Сегодня», «Цель», «План и блок» (интерфейс — отдельный отчёт ниже).
- Проверено: `tests/learn.rs` — `clean_db_goal_plan_block_resume_and_close`, `goal_edit_validates_and_reorders`, `backlog_is_neutral_and_can_be_spread`; ручной CLI-прогон на временной базе (пауза по EOF, возобновление с шага 3, заметка и мысль в итоге).

### 2. Обучение, расписание, измерение — сделано в объёме ниже

- Виды заданий: `number`, `text` (варианты), `expr` (SymPy в песочнице, область `positive|real`), `code` (Python с тестами в песочнице), `card` и `explain` (самооценка по эталону и рубрике). В диагностике и контроле — только автоматическая оценка.
- Попытка хранит версию задания, способ оценивания (`graded`), помощь (`hint`), роль (`diag`, `new`, `review`, `retry`, `test7`) и прогноз FSRS перед повторением (`p_recall`). Правка задания без смены `v` получает новую версию, формы — в `item_version`; старые результаты не переоцениваются; отмена сохранения — новая версия из прошлой редакции.
- FSRS: самооценка «с трудом» → `Hard` (закрывает вопрос из MVP о сигнале Hard), ответ после подсказки → `Again`, повтор после разбора — отдельный факт без влияния на срок.
- Горизонты: 7 дней (D5, первичный) и 30 дней — отдельная группа целей (`role = "test30"`, одна цель — один срок). День 1 не добавлен, чтобы не раскрывать недельную форму.
- «Прогресс»: удержание по сроку и домену, первые самостоятельные попытки по навыку, прогноз FSRS и самопрогноз против факта, очередь, объём данных, время в комнате как контекст; у каждой доли числитель, знаменатель, правило, строки и отметка «мало данных» (< 5).
- Проверено: `thirty_day_form_is_a_separate_objective_group`, `edited_item_gets_new_version_and_old_result_stays`, `self_graded_card_uses_hard_and_never_enters_measurement`, `expression_equivalence_respects_domain`; смена часового пояса и пропуск дней — в `backlog_is_neutral_and_can_be_spread`.
- Не сделано: автоматическая адаптация сложности и перерывов (по заданию — только после данных пилота); рекомендации планировщика сейчас — фиксированные правила с причиной, их отменяет правка плана.

### 3. Домены — по одной траектории на домен

| Домен | Модуль | Что внутри |
| --- | --- | --- |
| Кибербезопасность | `modules/log-analysis.toml` | синтетические журналы sshd и веб-сервера, разметка шагов, диагностика, выбор метода с предпосылками |
| Математика | `modules/math-derivatives.toml` | производные, цепное правило, `expr` с областью значений, доказательство с рубрикой |
| Программирование | `modules/code-python.toml` | трассировка, отладка логической ошибки, функции с тестами в песочнице |
| Немецкий | `modules/german-a2.toml` | слова с артиклем в обе стороны, Wo?/Wohin?, письменный ответ, вопрос по выбранному тексту |
| Исследования | `modules/research-sources.toml` + `modules/sources/research-texts.md` | чтение по фрагментам, тезис своими словами, сопоставление, «утверждение и источник»; ссылки ведут на заголовки локального файла |
| Пользовательский | `modules/template.toml`, импорт TOML и Anki | шаблон с описанием полей, редактор в окне |

Проверено тестом `every_domain_module_runs_from_goal_to_delayed_check`: у каждого задания с автоматической оценкой эталон проходит свою оценку, неверный ответ — нет; по каждому домену офлайн проходит цель → блок → «изучено» → проверка через 7 дней → удержание по домену в «Прогрессе».

Редактор материала: `module_preview` показывает новые, изменённые (с числом попыток), исключённые (остаются в истории) и пилотные цели; `module_save`, `module_undo`; CLI `whiteroom module check`.

Anki: импорт «Notes in Plain Text» (два поля через табуляцию, строки `#…` пропускаются, `<br>` → перевод строки) в карточки `card`; экспорт заданий в TSV. Переносятся только вопрос и ответ; история повторений, расписание, теги и медиа Anki не переносятся. Повторный импорт после экспорта сохраняет поля (тест). `.apkg` не поддерживается. IDE-интеграции не добавлялись: наблюдаемой потребности нет.

### 4. Тьютор, данные пользователя — частично

- Тьютор, предпросмотр и отмена — без изменений с MVP (D10, D16, D17), их тесты проходят.
- «Что WHITE ROOM видит сейчас» (`seen`): запись по источникам текущей сессии и способ отзыва, размер базы и журналов, копии, число строк журналов, интеграции (native host, таймер D1, ключ Claude в окружении). Тест `seen_screen_reports_capture_off_without_session`.
- Резервная копия `backup` (VACUUM INTO, без перезаписи), восстановление `restore` (проверка целостности и схемы, текущая база сохраняется рядом), автоматическая копия перед миграцией, установщик делает копию перед обновлением.
- Полный экспорт дополнен новыми таблицами. Синхронизация D1 идёт по явному списку столбцов (`scripts/progress_sync.py`): цели, блоки, заметки, мысли и рефлексия туда **не попадают**.
- Очистка записей активности (D21): хранение до ручной очистки; «Очистить записи активности» для завершённой сессии или записей без сессии со счётом до удаления; CLI `whiteroom clear`, команда окна `activity_clear`. Подробности и проверка — в [карте данных](local-data-inventory.md#решение-перед-реализацией-очистки). Новых платных вызовов и генерации заданий в этой работе не было.

### 5. Окружение и выпуск

- Версии 1.0.0 (CLI, окно), схема БД 2, протокол расширения 1 (manifest 1.0). Более новая схема → понятная ошибка без открытия; окно сверяет версию соседнего CLI (`versions`); расширение при другом протоколе пишет «Версии не совпадают» и, как при потере связи (D8), не трогает правила до ручного снятия. Фикстура `a host with another protocol version keeps rules and names the mismatch`.
- Установка: `install.sh` из архива → `~/.local/bin`, `~/.local/share/whiteroom/{modules,extension}`, ярлык. Профиль браузера и native messaging не меняет.
- Замер фона (2026-11-20, Hyprland, release, временная база, сессия без записи): `whiteroom timer-watch` — 6,7 МБ RSS, < 0,05 % CPU; Quickshell-таймер — 239 МБ RSS, ~0,6 % CPU за первые 42 с с учётом запуска. Трекер окон без согласия не запускается.

## Пилот и решение о выпуске

Протокол D5 (предложение, требует утверждения владельцем до сбора данных):

1. Темы: две пары сопоставимых целей из одного модуля (например, `logs-auth`/`logs-web`), у каждой по 2 невиданные формы `test7`.
2. Назначение: внутри человека, цели пары случайно в `wr` и `usual` (`whiteroom init`), равный бюджет учебного времени (`outside_min` для `usual`, минуты блока для `wr`).
3. Контроль исходного знания: диагностика `diag` до учёбы, одинаковая для обеих групп.
4. Промежуточные повторения: только в `wr` по FSRS. Пропуск — нет ответа к сроку + 2 дня; опоздание считается отдельно, не как первый ответ.
5. Окно проверки: день 7 ± 2 дня; день 30 — отдельная группа целей.
6. Эффект — разница долей первых ответов в окне на уровне сопоставленных пар целей, с числом наблюдений и интервалом (при n < 30 — точный интервал, вывод не делается). На синтетике проверено ручным подсчётом (`pilot_report_matches_hand_count`).

Решение: **технический выпуск 1.0 — готов к локальной установке** при условиях, перечисленных в «Не проверено». Вывод о влиянии на удержание не делается: реальных наблюдений нет.

Отдельные этапы (не включены): автоматическая адаптация, n-of-1, другие WM и браузеры, IDE-интеграции, новые провайдеры, день 1, импорт `.apkg`.

## Не проверено

- Снятие правил при недоступном хосте из UI расширения в этой версии (фикстуры есть, ручной прогон — с M1/D8).
- Настоящее окно на нативном Wayland и на 360 px; самооценка, экран «Цель» и импорт через выбор файла в настоящем окне.
- Публикация, установка в рабочий профиль, миграция рабочей базы владельца — по отдельной команде.
